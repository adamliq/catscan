# aws/

Data and build tooling for the **AWS Events** tab (Action Explorer) in
the top-level `index.html`, mirroring how `windows/`, `linux/`, and
`threat-detection/` hold each of those catalogues' own data.

Unlike those three, this catalogue isn't sourced from an external repo —
it's built directly from [`Events_Other/aws_iam_actions_expanded.csv`](../Events_Other/README.md).

- `data/aws_iam_actions.json` — every row of that CSV, reshaped into one
  JSON object per AWS IAM action (`id`, `service`, `action`, `awsService`,
  `description`, `resourceTypeConsole`, `resourceType`, `eventType`,
  `eventCategory`, `eventName`, `acscRecommended`, `acscLoggingCondition`)
  under an `actions` array, plus `actionCount`/`serviceCount` summary
  fields. `index.html`'s AWS Events tab `fetch()`es this file at runtime
  rather than embedding it inline — same reason and same trade-off as
  Threat Detection's Heat Coverage tab (see the top-level README): it
  needs the page served over http(s), not opened as a local `file://`.
- `tools/build_aws_json.py` — regenerates `data/aws_iam_actions.json`
  from the CSV. Run it (`python3 aws/tools/build_aws_json.py`) after
  updating `Events_Other/aws_iam_actions_expanded.csv`; it never touches
  `index.html`, which stays generated by the separate merge script the
  same way it already is for the other three catalogues.
